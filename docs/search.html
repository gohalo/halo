Halo 主题全站搜索实现方案

基于 Hugo 构建期索引 + FlexSearch 纯前端检索 + 原生 <dialog> 命令面板，多语言、离线可用、无需后端。

1. 总体架构

Hugo 构建期                                  浏览器运行期
─────────────────────────────────────       ────────────────────────────────────
页面内容
  └─ 按标题切分（function/search/fragments）
       └─ 生成 {lang}.search-data.json  ──→  fetch（首次打开搜索时懒加载）
                                              └─ FlexSearch.Document × 2
                                                   ├─ pageIndex    整页索引（分组用）
                                                   └─ sectionIndex 片段索引（命中定位）
                                                        └─ 查询 / 排序 / 去重
                                                             └─ <dialog> 面板渲染 + 高亮

核心设计：构建期只产出数据，运行期只做检索和渲染。没有服务端接口，不与搜索服务耦合，站点可部署到任意静态托管。

2. 文件职责

文件阶段职责
assets/json/search-data.json 构建期 Hugo 模板：筛选页面，调用片段切分 partial，输出 JSON 索引数据。
layouts/_partials/function/search/headings.html 构建期 把 .Fragments.Headings 拍平成 [{id, title, level}]，保持文档顺序。
layouts/_partials/function/search/collect.html 构建期 递归收集嵌套标题树到 Scratch。
layouts/_partials/function/search/fragments.html 构建期 按标题把正文切分成可搜索片段，支持 content / heading / title / summary 四种模式。
layouts/_partials/head/search.html 构建期 注册索引资源、加载 FlexSearch 运行时与两个前端脚本（按语言生成、生产环境压缩 + 指纹）。
package.json + exampleSite/config/_default/hugo.yaml 构建期 FlexSearch 作为 devDependency 安装，并通过 module.mounts 把 node_modules/flexsearch/dist 挂载到 static/flexsearch（与 katex / mermaid / reveal 的方式相同）。
assets/js/flexsearch.js 运行期 数据层：懒加载 JSON、建索引、执行查询、返回分组结果（window.haloSearch）。
assets/js/search-dialog.js 运行期 交互层：dialog 开关、快捷键、键盘导航、ARIA、结果渲染与关键词高亮。
layouts/_partials/component/search.html 构建期 <dialog> 面板结构。
layouts/_partials/header/search.html 构建期 文档页顶部搜索栏样式的触发器。
layouts/_partials/header/icons/search.html 构建期 导航栏搜索图标触发器。
assets/css/search.css 运行期 面板样式。全部使用原生 CSS + 主题 CSS 变量，不依赖 Tailwind 扫描。
i18n/{zh,en}.yaml 构建期 search_placeholder、search_no_results、search_results_found 等文案。
模板挂载点：layouts/baseof.html（普通页面）、 layouts/docs/baseof.html（文档列表）、 layouts/docs/single.html（文档详情）都必须引入 component/search.html。 文档页使用独立的完整 HTML 模板，不继承根 baseof.html，遗漏会出现"有搜索框但点击无反应"。

3. 构建期：索引数据生成

3.1 页面筛选

assets/json/search-data.json 的筛选规则：

{{- $pages := where .Site.Pages "Kind" "in" (slice "page" "section") -}}
{{- $pages = where $pages "Params.searchable" "!=" false -}}
{{- $pages = where $pages "Content" "!=" "" -}}
  • 只索引 page 与 section，排除 taxonomy / term / home 等。
  • 页面 front matter 设置 searchable: false 可排除单页（默认 true，即默认参与搜索）。
  • 没有正文的页面不进入索引。

每页标题取 LinkTitle，缺失时回退到文件名：

{{- $pageTitle := .LinkTitle -}}
{{- if not $pageTitle -}}
    {{- with .File -}}{{- $pageTitle = .BaseFileName -}}{{- end -}}
{{- end -}}

3.2 标题提取

使用 Hugo 的 Page.Fragments（由正文渲染结果生成，ID 与页内锚点一致），递归拍平：

# 页面标题树
.Fragments.Headings
  ├─ { ID: "intro", Title: "Introduction", Level: 1, Headings: [...] }
  └─ ...

# 拍平结果
[
  { id: "intro", title: "Introduction", level: 1 },
  { id: "setup", title: "Setup", level: 2 }
]
  • .Fragments.Headings 顶层可能包含一个 Level 0、无标题的虚拟根节点，递归收集时会跳过它但保留其子标题，避免生成 "#" 这类空片段键。
  • 标题是否成立完全由 Hugo/Goldmark 的渲染结果决定：只有渲染成 <hN> 的才是标题，正文或代码块中以 # 开头的行仍属于内容文本，本方案不会按 Markdown 的 # 语法做二次解析。
  • 标题文本本身可能包含 #（如 "C#"），片段键使用「ID#标题」格式，前端按第一个 # 拆分，因此标题中的 # 会被完整保留。

3.3 片段切分算法

function/search/fragments.html（content 模式）从页面 HTML 中按标题切分，采用 自下而上 的方式，避免上层标题重复处理已切走的片段：

{{- range seq $len -}}
    {{- $i := sub $len . -}}                       {{/* 从最后一个标题开始 */}}
    {{- $heading := index $headings $i -}}
    {{- $opening := printf "<h%d id=\"%s\"" $heading.level $heading.id -}}
    {{- $endTag := printf "</h%d>" $heading.level -}}

    {{- $parts := split $content $opening -}}
    {{- if gt (len $parts) 1 -}}
        {{- $before := index $parts 0 -}}
        {{- $rest := delimit (after 1 $parts) $opening -}}
        {{- $sub := split $rest $endTag -}}
        {{- if gt (len $sub) 1 -}}
            {{- $fragment := delimit (after 1 $sub) $endTag -}}
            {{- $text := $fragment | plainify | htmlUnescape | strings.TrimSpace -}}
            {{- $data = $data | merge (dict (printf "%s#%s" $heading.id $heading.title) $text) -}}
            {{- $content = $before -}}             {{/* 剩余内容继续处理上面的标题 */}}
        {{- end -}}
    {{- end -}}
{{- end -}}
  • 定位标记为 <hN id="锚点"，因此要求 render-heading.html 输出标准 id 属性；自定义 render hook 不符合此格式时会退化为空片段。
  • 直接使用原始 Page.Content 切分，不做前置 htmlUnescape：否则代码块里被转义的 <hN id="…"> 会被还原成真实标签，误判为标题边界；正文里字面的 <tag> 也会在 plainify 时被当作标签吞掉。
  • 片段是 </hN> 之后的正文，本身不包含标题内的锚点 #，因此不会剥离尾部 #，避免把恰好以 # 结尾的正文（如 "C#"）错误截断。
  • 最后一个标题切完后剩余的 HTML 作为前言片段，键为 ""。

3.4 四种索引模式

params.search.flexsearch.index行为适用
content（默认）按标题切分正文，保留标题与段落文档站，定位到具体小节
summary只索引 Page.Summary博客，结果轻量
heading只索引标题键，内容为空只要目录级检索
title只索引页面标题页面数量多、追求速度

3.5 JSON 结构

键为页面 RelPermalink，值为标题 + 片段字典（片段键为 锚点ID#标题文本，前言为 ""；前端按第一个 # 拆分，标题里的 # 不影响解析）：

{
  "/zh/blog/hello-world/": {
    "title": "Hello World",
    "data": {
      "": "页面开头段落……",
      "mermaid#Mermaid": "Mermaid 相关正文……",
      "目录-1#目录 1": "……"
    }
  }
}

资源按语言生成：{lang}.search-data.json；生产环境执行 minify | fingerprint。

4. 运行期：索引构建

assets/js/flexsearch.js 在首次打开搜索框或首次输入时才 fetch 数据（preloadIndex()），并用 Promise 缓存，避免重复加载；失败会清空缓存以便下次重试。

4.1 两个 Document 索引

索引存储字段用途
pageIndex title、breadcrumbs、content（整页文本） 决定“命中哪些页面”并作为结果分组标题。
sectionIndex title、content、url、display、crumb，并按 tag: pageId 归属页面 决定“页面内命中哪些小节”，提供跳转锚点与摘要。 
pageIndex = new FlexSearch.Document({
  tokenize, encode, cache: 100,
  document: { id: 'id', store: ['title', 'breadcrumbs'], index: 'content' }
});

sectionIndex = new FlexSearch.Document({
  tokenize, encode, cache: 100,
  document: {
    id: 'id',
    store: ['title', 'content', 'url', 'display', 'crumb'],
    index: 'content',
    tag: [{ field: 'pageId' }]
  }
});

每个片段除自身外还会额外写入一条只含标题的文档（带 display），用于判断“标题命中”并参与排序。

4.2 中日韩分词

FlexSearch 默认分词不适用于无空格语言。这里的 encode 对 CJK / 日文假名 / 韩文输出「单字 + 相邻双字（bigram）」，其他语言（拉丁/西里尔/阿拉伯等）按完整单词输出：

// "页面" => ["页", "面", "页面"]
encode("页面");
// "静态页面搭建" => ["静","静态","态","态页","页","页面","面","面搭","搭","搭建","建"]
  • 单字 token 保证「页」这类单字查询能命中。
  • bigram token 保证「页面」这类词组查询要求两个字连续出现，避免同一段落里分散出现的「页」「面」造成误命中。
  • 多个 token 的查询在 FlexSearch 中按 AND 处理；配合 tokenize（默认 forward，前缀匹配）可支持输入过程中的增量检索。
  • 若查询完全无结果，会退化为「每字一个 token」（如把 页面 转成 页 面）再检索一次，作为召回兜底。
  • 不使用 suggest: true：它会放宽多 token 查询，导致「页面」命中只包含「页」或「面」的小节。
  • 输入法组合期间（isComposing）不触发检索，并在 compositionend 后补触发一次，避免组合输入完成后没有结果。

4.3 面包屑

由 RelPermalink 逐级累加（如 /zh/docs/basic/about/ → /zh/、/zh/docs/、…），在 JSON 中查找对应页面标题拼接为 Docs > Basic Docs > Basic About。若中间层级未建索引（被排除），该级自动跳过。

5. 查询与结果结构

1. pageIndex.search(query, maxPageResults, { enrich: true })
2. 对每个命中页面：
     sectionIndex.search(query, {
       enrich: true,
       tag: { pageId: `page_${pageId}` }
     })
   若所有页面均无结果：将 CJK 拆为单字（relaxQuery）后重试一次
3. 片段去重：url + '@' + content
4. 统计每个页面的“标题命中数”
5. 排序：标题命中数降序 → 页面相关度顺序
6. 截断：页面 maxPageResults，片段 maxSectionResults

返回结构：

[{
  id: "halo-search-opt-0",
  route: "/zh/docs/basic/about/",
  title: "Basic About",
  breadcrumbs: ["Docs", "Basic Docs"],
  matches: [{
    id: "halo-search-opt-1",
    route: "/zh/docs/basic/about/#intro",
    title: "Introduction",
    content: "片段摘要……"
  }]
}]

6. 交互与可访问性

  • 触发入口：导航栏图标（menu.icons 中加入 name: "search"）、文档页顶部搜索栏；所有入口统一使用 data-search-open。
  • 快捷键：⌘K / Ctrl+K 切换；/ 打开（输入框 / contenteditable / 按钮中不触发）。
  • 键盘导航：↑ ↓ Home End 在结果间移动，Enter 打开当前项，Esc 关闭；鼠标悬停与焦点都会同步高亮。
  • 输入法：组合输入期间（isComposing / keyCode === 229）不处理键盘事件，避免选词被截获。
  • ARIA：输入框 role="combobox" + aria-controls + aria-activedescendant，结果 role="listbox" / option，状态文案通过 role="status" 播报。
  • 竞态处理：异步查询返回时若输入框内容已变化，丢弃旧结果。
  • 动画：面板入场/退场与遮罩动画；prefers-reduced-motion 时直接关闭。
  • 保持现场：重新打开时保留上次查询与结果，仅重置 ARIA 状态。
  • 高亮：按查询词做正则转义后 split 渲染，命中部分包 <span class="halo-search-match">，不注入 HTML。

7. 第三方依赖加载（与 katex 一致）

  • 依赖声明：package.json 的 devDependencies 增加 flexsearch，通过 npm install 安装。
  • 目录挂载：hugo.yaml 的 module.mounts 将 ../node_modules/flexsearch/dist 挂载到 static/flexsearch，构建时随 static 目录一起发布。
  • 页面引用：head/search.html 直接输出 <script defer src="{{ "flexsearch/flexsearch.bundle.min.js" | relURL }}">， 与 katex / mermaid / reveal 的引入方式一致；不在构建期下载，也不把库文件提交到仓库。
  • 路径覆盖：params.search.flexsearch.js 可指定其他静态路径或完整 URL。
  • 索引 JSON 与业务脚本仍走 Hugo 资源管线（生产环境 minify + fingerprint + integrity）。
使用前提：与 katex 等库相同，站点需要执行 npm install 并在自己的 hugo.yaml 中配置相同的 mount。 exampleSite 已配置，可直接参考： source: ../node_modules/flexsearch/dist → target: static/flexsearch。

8. 多语言

  • 每个语言生成独立的 {lang}.search-data.json 与 {lang}.flexsearch.js、{lang}.search-dialog.js。
  • 脚本在同一站点内跨语言共享（发布在站点根路径），页面按自身语言引用对应文件。
  • 界面文案通过 i18n 注入；缺失的翻译使用英文默认值。

9. 配置项

params:

    enable: true

      # js: "js/my-flexsearch.js"     # 自定义本地运行时（assets 下）
      # base: "https://cdn.example.com/flexsearch"  # 远程运行时目录

    search:
      enable: true

10. 扩展与排查

10.1 页面点开搜索没反应

  1. 检查该页面使用的 base 模板是否引入了 component/search.html（文档页、独立版式最容易遗漏）。
  2. 在 DevTools 中执行 document.getElementById('halo-search-dialog')，返回 null 即为未引入。
  3. 确认 params.search.enable 未被关闭。

10.2 搜索无结果或结果缺失

  1. 确认页面有正文且未设置 searchable: false。
  2. 检查自定义 render-heading.html 是否输出 <hN id="…">，片段切分依赖该格式。
  3. 调整 index 模式（如 content → summary）或减小 maxSectionResults 观察差异。

10.3 控制台出现 Context-Search 警告

FlexSearch 在非 strict 分词下会输出 Context-Search could not applied，属于库内提示，不影响检索结果；如需消除可忽略或改用 tokenize: "strict"。

10.4 本地多开 Hugo Server

多个 hugo server 同时运行可能争用构建锁，导致未缓存页面长时间等待。排查时使用新端口并加 --noBuildLock 验证；确认问题在进程状态后重启 server。
